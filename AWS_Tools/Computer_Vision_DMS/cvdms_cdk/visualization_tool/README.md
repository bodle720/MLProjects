# CVDMS Dataset Viewer

A local Streamlit dashboard for inspecting CVDMS dataset visualization artifacts.

This tool is meant to be a lightweight, private, TensorBoard-like viewer for dataset versions created by the CVDMS DatasetStack. It does not recompute dataset analytics from scratch. It reads the JSON artifacts generated by the Dataset Visualization Lambda and renders them as interactive charts, tables, and diagnostics.

## Expected S3 Layout

The viewer expects CVDMS dataset artifacts in the datasets bucket under:

```text
datasets/<dataset_id>/v<version>/visualization/
```

For example:

```text
datasets/eurosat_demo/v1/visualization/overview.json
datasets/eurosat_demo/v1/visualization/class_distribution_by_split.json
datasets/eurosat_demo/v1/visualization/source_distribution_by_split.json
datasets/eurosat_demo/v1/visualization/source_split_resolution_by_split.json
datasets/eurosat_demo/v1/visualization/quality_distribution_by_split.json
datasets/eurosat_demo/v1/visualization/numeric_feature_summary.json
datasets/eurosat_demo/v1/visualization/numeric_feature_histograms.json
datasets/eurosat_demo/v1/visualization/split_comparison_metrics.json
```

These are produced by the CVDMS visualization Lambda after dataset create/update completes.

## Installation

From your project environment, install the required packages:

```bash
pip install streamlit boto3 pandas plotly
```

If you prefer to keep this separate from your CDK/runtime environment, create a small local virtual environment first:

```bash
python -m venv .venv-viz
.venv-viz\Scripts\activate
pip install streamlit boto3 pandas plotly
```

On macOS/Linux:

```bash
python -m venv .venv-viz
source .venv-viz/bin/activate
pip install streamlit boto3 pandas plotly
```

## Running the Viewer

From the project root:

```bash
streamlit run visualization_tool/cvdms_dataset_viewer.py
```

Or from inside the visualization tool folder:

```bash
cd visualization_tool
streamlit run cvdms_dataset_viewer.py
```

## AWS Profile, Region, and Bucket

You do not need to set environment variables to use the viewer.

When the Streamlit app opens, the sidebar includes editable fields for:

- AWS profile
- AWS region
- CVDMS datasets bucket

Enter those values directly in the app.

Environment variables are only used as optional defaults to pre-fill the sidebar fields. The app does not require them.

The app uses `boto3`, so it follows normal AWS credential resolution.

You can either:

1. Leave the AWS profile field blank and rely on the default credential chain, or
2. Enter an AWS profile name in the sidebar, such as:

```text
default
personal
cvdms-dev
```

On Windows PowerShell:

```powershell
$env:AWS_PROFILE="your-profile"
$env:AWS_REGION="us-east-1"
$env:CVDMS_DATASETS_BUCKET="your-datasets-bucket"
streamlit run visualization_tool/cvdms_dataset_viewer.py
```

On Windows Command Prompt:

```cmd
set AWS_PROFILE=your-profile
set AWS_REGION=us-east-1
set CVDMS_DATASETS_BUCKET=your-datasets-bucket
streamlit run visualization_tool/cvdms_dataset_viewer.py
```

On macOS/Linux:

```bash
export AWS_PROFILE=your-profile
export AWS_REGION=us-east-1
export CVDMS_DATASETS_BUCKET=your-datasets-bucket
streamlit run visualization_tool/cvdms_dataset_viewer.py
```

## Sidebar Controls

The sidebar lets you select:

* AWS profile
* AWS region
* CVDMS datasets bucket
* Dataset ID
* Manual dataset ID override
* Dataset version
* Whether to show the raw artifacts tab

The app can discover dataset IDs from:

```text
s3://<datasets-bucket>/datasets/
```

It discovers versions from:

```text
s3://<datasets-bucket>/datasets/<dataset_id>/
```

Versions are expected to use folder names like:

```text
v1/
v2/
v3/
```

By default, the version dropdown only shows versions containing:

```text
visualization/overview.json
```

## Dashboard Tabs

### Overview

Shows:

* dataset ID
* version
* label type
* row count
* honor source splits setting
* effective split mode
* train/val/test counts
* train/val/test percentages

### Suggestions

Shows deterministic diagnostics based on the loaded artifacts.

Examples:

* empty or tiny validation/test split
* classes present in train but missing from val/test
* sources present in train but missing from val/test
* class distribution drift
* source distribution drift
* unresolved or inconsistent source split records
* quality bucket drift

These suggestions are intentionally rule-based and transparent.

### Class Balance

Uses:

```text
class_distribution_by_split.json
```

Renders class counts and percentages by split.

For single-label and multi-label datasets, this is based on labels. For object detection, semantic segmentation, and instance segmentation, this is based on `classes_present`.

### Source Balance

Uses:

```text
source_distribution_by_split.json
```

Renders source counts and percentages by split.

This is useful for checking whether one source is overrepresented in train or missing from validation/test.

### Source Split Resolution

Uses:

```text
source_split_resolution_by_split.json
```

Renders:

* source split status by final split
* resolved source split by final split

This is especially useful when `honor_source_splits=True`.

### Quality Buckets

Uses:

```text
quality_distribution_by_split.json
```

Renders distributions for:

* lighting bucket
* blur bucket
* contrast bucket
* color bucket

This helps identify cases where train/val/test differ in image quality.

### Numeric Features

Uses:

```text
numeric_feature_summary.json
numeric_feature_histograms.json
```

Renders summaries and histograms for numeric image features such as:

* image height
* image width
* file size
* luma statistics
* dark/bright fraction
* contrast
* blur variance
* saturation
* colorfulness

### Split Comparison

Uses:

```text
split_comparison_metrics.json
```

Shows val-vs-train and test-vs-train drift for:

* class distribution
* source distribution

This is one of the most useful tabs for determining whether validation/test are representative of training.

### Raw Artifacts

Optional debugging tab.

Shows the raw loaded JSON artifacts directly in Streamlit.

## Design Philosophy

This viewer is intentionally local and lightweight.

The CVDMS DatasetStack is responsible for creating durable versioned artifacts. The Streamlit app is only a consumer of those artifacts. This keeps the backend workflow stable while allowing the UI to evolve quickly.

The intended workflow is:

```text
1. Create or update a dataset through CVDMS.
2. Dataset workflow writes visualization artifacts to S3.
3. Run this local Streamlit viewer.
4. Select dataset ID and version.
5. Inspect charts and suggestions.
6. Decide whether the dataset is healthy or needs another update/rebalance.
```
